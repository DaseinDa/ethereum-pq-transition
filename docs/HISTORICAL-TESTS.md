# Current and historical client tests

The current geth test sources cover the F profile (verifier version `0x80000008`) and the optional four-owner C aggregate. Their native verifier cases require the `pq_final,pq_aggregate` build tags and the corresponding libraries and public fixtures; a plain untagged test run does not establish native F/C verification. The public F fixtures under `prover/final-verifier/fixtures/mode0` through `mode3` include the original proof, original PI198, and source hashes. Their original F statement metadata pins key `ed2fcf813b942404729da7827c4743020dae8d89ebbc206e5bee7718503df3f2`. Tests replay each proof at `expiry - 3600` in an explicit component pre-state. This does not establish a new live recovery or freshness on today's chain. The C tests use two public four-owner fixtures under `prover/aggregate/fixtures`: `four-owner` (four fee-mode-2 entries with one expiry, replayed at `expiry - 3600`) and `four-owner-gates` (one entry expiring before the other three, a fee-mode-3 entry, a fee-mode-1 entry naming the test sponsor, and an entry bound to migration nonce 1, replayed 1,800 s after the first expiry in a two-block import whose first block carries a real `0x7d` by that entry's public legacy key); `PQ_BATCH_CARRIER`/`PQ_BATCH_STATEMENT` and `PQ_BATCH_GATES_CARRIER`/`PQ_BATCH_GATES_STATEMENT` name them.

Set `PQ_F_FIXTURES` to that directory, `PQ_F_PROOF` and `PQ_F_PI` to mode0's `proof.postcard` and `pi198.hex`, and build the native client with `pq_final,pq_aggregate`. The package build script sets the public fixture defaults. The F execution suite uses the native verifier for fee modes 0, 1, 2 and 3 and the exact enrollment override deadline. The state boundary suite separately checks T0/T, expiry, activation and override state, reimbursement, first-failure codes, and real ML-DSA sponsor signatures. Its synthetic state-only carriers are never asserted to prove ownership.

The old external-worker/Composite suites are retained under the explicit `pq_historical` Go build tag. They describe the October 2026 chain13375/version0x80000002 experiment and are excluded from the default test build. The current client rejects that historical profile, and enabling the tag does not restore it or turn its old results into current-F evidence. Archived source includes the old Full integration, fee-mode, override, pool lifecycle and pool boundary tables. In `core/txpool/pqpool`, all four files `mode0_test.go`, `full_integration_test.go`, `boundary_test.go`, and `lifecycle_integration_test.go` carry the same `pq_historical` tag. In particular, `mode0_test.go` calls `actualHistoricalProfile`, whose definition remains in the equally tagged `full_integration_test.go`; moving that skip helper into an untagged file would bring archived skips back into the default suite.

Current pool sources are separate: `pqpool_test.go` exercises component admission, replacement and budgets; `pq_reset_sponsor_test.go` exercises held-entry reset ordering; `pq_final_boundaries_test.go` contains `TestPQCurrentFPoolAdmissionBoundaries` and `TestPQCurrentFHeldPoolRevalidatesBoundaryHeads` using the public single-F fixtures and default verifier hooks; `batch_test.go` contains the current C admission/retention tests. Core state and execution sources are `pq_final_state_test.go`, `pq_final_fixtures_test.go`, and `pq_batch_test.go`. These are source-coverage locations, not a claim that their tests have compiled or passed.

A separate build without the native tags exercises the fail-closed no-library paths. Native tests must not be reported as passed until their tagged build has actually run. Source porting, formatting, helper-reference scans, and fixture hash checks alone are not execution evidence.

The helper-isolation checks are `go vet ./core/txpool/...` with and without the native tags, `go test ./core/txpool/...`, `go test -tags pq_final,pq_aggregate ./core/txpool/...`, the `geth-test` stage of `tools/build.py`, and the compile check `go test -tags pq_historical -run '^$' ./core/txpool/pqpool/`. Use the native libraries and packaged fixture environment for the tagged native lane. Use a separate environment without the native fixture variables for the plain and historical lanes. The historical command checks that the archive still compiles; its explicit profile skips do not count as current-profile coverage. On 2026-11-10 all of them passed on the reconstructed source with geth patches 0001 to 0005. Counting subtests, the plain `./core/txpool/...` run had 280 passed, 0 failed and 39 skipped, the tagged run 316, 0 and 3, and `geth-test` 845, 0 and 27. Both vet lanes and the historical compile were clean.

The obsolete `cmd/pqr1e1` and `cmd/pqrow11` experiment executables and the unreachable external-worker verification fallback have been removed. Two optional facilities remain because they are reachable and used: the separately pinned native Succinct profile, accepted only under its explicit algorithm identity and native build, and `PQStateBridge`, used by the authenticated N1 checkpoint/import path. Neither replaces F or C, neither is silently selected for the default F configuration, and their presence does not claim that the older proof experiments are reproduced by the current default tests. Removing the bridge would disable the checkpoint path, not merely remove unused research code.

Contributor notices and SPDX identifiers were added to new Go source files while retaining existing upstream notices and licence text where derivation could require them. Existing upstream files were not reattributed. Go source files are ordinary non-executable source (`0644`).
